# Engineering notes

How OSAKA was made dependable: the technical problems solved along the way and the decisions behind the design.

## Problems solved

| Area | Challenge | Solution |
|---|---|---|
| **Run status** | Finished runs needed to show as finished in n8n's Executions view. | Successful runs are saved and auto-pruned after 72 h (`EXECUTIONS_DATA_MAX_AGE`), so every run reports a definitive status. |
| **Error handling** | n8n won't execute a workflow while any node has an unconfigured credential, so a Gmail alert node would block local error logging. | The error workflow writes a local structured log, and email alerts live in a separate sub-workflow that is called only when configured. Error workflows are published, as n8n 2.x requires. |
| **Recovery** | A file-watch trigger only sees new events, so a file dropped during downtime would be missed. | A 10-minute sweeper re-offers every pending PDF. The app deduplicates by content hash, so finished files cost one DB lookup. Verified by dropping files during app and n8n outages: both were recovered automatically. |
| **Request signing** | Batches that take minutes would outlive a ±300 s signature window. | A single-item loop signs each request immediately before it is sent. |
| **Scanned PDFs** | The native canvas module that renders page images must load at runtime, not be bundled. | `serverExternalPackages` for `@napi-rs/canvas` and `unpdf`, and documents are opened with an explicit `CanvasFactory` so pdf.js renders real pixels. |
| **Vision** | Images must reach the model correctly for scanned documents. | Pinned and verified the model build. Every result stores the model digest, so any model change is visible. |
| **Deterministic output** | Free-form LLM output is hard to trust. | Thinking disabled, JSON-schema-constrained decoding, temperature 0, fixed seed, and automatic retry on malformed output. |
| **Local file trigger** | n8n 2.x ships with the Local File Trigger disabled. | Enabled that single node (Execute Command stays disabled), with file access confined to the drop folder. |

## Design decisions

- **Human-approved records.** Model output is a draft; a reviewer's approval creates the record. This keeps the data trustworthy while the model does the heavy lifting.
- **The database owns state, n8n orchestrates.** A retried n8n run asks the database what is already done, so it can never double-reply or double-append.
- **Confidence from evidence.** Required-field coverage, the share of values found in the text, and arithmetic cross-checks, never the model's opinion of itself.
- **Workflows as code.** n8n workflows are generated by a script, reviewed in pull requests, and checked by CI against the committed JSON. The README diagrams are rendered from the same files.
